# Feature Spec: 任务调度与按 URL 检索系统

## Overview

在现有的浏览器上下文管理和任务执行框架之上，新增**定时任务调度**、**按 URL 检索**、**任务断点续跑**和**商品链接结构化存储**四项核心能力。用户可以为任务设置定时规则（间隔秒数或 cron 表达式），系统自动周期性执行；`search_by_urls` 脚本自动打开已采集的商品链接提取最新价格；采集结果从 JSON 大字段拆分为结构化的商品链接表，支持分页查询、过滤和下载。

## Problem Statement

当前系统存在以下问题：
1. **没有定时调度**：每次执行任务都需要手动触发，无法设置周期性巡检（如每小时检查一次价格）
2. **采集结果不可查询**：任务结果存在 Task.result 的 JSON 字段中，无法按平台、关键词筛选，也无法下载
3. **任务失败无法续跑**：任务失败或取消后，只能重新创建任务从头开始，已采集的数据被浪费
4. **没有按 URL 检索能力**：采集到商品链接后，无法自动回访这些链接获取最新价格

## User Scenarios & Testing

### 场景 1：创建定时采集任务
- 用户创建一个淘宝链接采集任务，设置定时规则为 `3600`（每 3600 秒执行一次）
- 系统保存定时规则到任务记录
- 调度器按规则自动触发任务执行
- 任务完成后更新 `last_run_at` 时间戳
- 下次调度时间到达时自动再次执行

### 场景 2：按 URL 检索
- 用户创建一个 `search_by_urls` 类型的任务，关联一个已登录的浏览器上下文
- 系统自动从该任务关联的商品链接中取出所有 URL
- 逐个打开商品页面，检测平台并使用对应的价格提取逻辑
- 提取到的价格更新到 ProductLink 记录中
- 巡检完成后返回总数、成功数、失败数

### 场景 3：任务断点续跑
- 一个淘宝采集任务在第 3 页失败
- 用户点击"重试"按钮
- 系统复用同一个任务记录，保留已采集的 ProductLink 数据
- 脚本从上次中断的页码继续采集
- 新采集的链接通过 upsert 去重合并

### 场景 4：查看和下载采集结果
- 用户在任务详情页查看已采集的商品链接列表
- 支持按平台、关键词过滤
- 支持分页浏览
- 用户可以下载全部结果为 JSON 文件

### 场景 5：取消正在运行的任务
- 用户取消一个处于 RUNNING 或 WAITING_HUMAN_INPUT 状态的任务
- 系统同时取消底层的 asyncio Task
- 释放浏览器上下文锁
- 任务状态变为 CANCELLED

### 验收场景
- 任务可以设置定时规则，调度器按规则自动触发
- 按 URL 检索能正确提取淘宝、京东、天猫的商品价格
- 失败/取消的任务可以通过 retry 接口续跑，已采集数据不丢失
- 商品链接支持按平台/关键词分页查询和下载
- 取消任务能立即停止 asyncio 协程并释放上下文
- 多平台脚本（JD、天猫、淘宝搜索）均可作为任务类型创建

## Functional Requirements

### FR-1: 定时任务调度
- FR-1.1: Task 模型支持 `schedule` 字段，存储定时规则（秒数间隔或 cron 表达式）
- FR-1.2: Task 模型支持 `last_run_at` 字段，记录上次执行时间
- FR-1.3: 系统提供调度器，定期扫描到期的定时任务并触发执行
- FR-1.4: 定时任务执行完成后自动更新 `last_run_at`
- FR-1.5: 同一上下文的定时任务不会并发执行（互斥）

### FR-2: 按 URL 检索
- FR-2.1: 支持创建 `search_by_urls` 类型的任务
- FR-2.2: 巡检脚本自动从关联的 ProductLink 记录中提取商品 URL
- FR-2.3: 逐个打开商品页面，自动检测平台（京东、淘宝、天猫、1688）
- FR-2.4: 使用平台专属 JS 提取逻辑获取当前价格
- FR-2.5: 将提取到的价格更新到 ProductLink 记录
- FR-2.6: 巡检过程中支持任务取消
- FR-2.7: 返回巡检统计：总数、更新成功数、失败数

### FR-3: 任务断点续跑
- FR-3.1: 支持对 FAILED 或 CANCELLED 状态的任务发起重试
- FR-3.2: 重试时复用原任务的 ID、参数和上下文
- FR-3.3: 已采集的 ProductLink 数据保留，通过 upsert 去重
- FR-3.4: 脚本支持 `start_page` 参数，从中断页码继续
- FR-3.5: 重试时重置任务状态（进度、错误、日志、时间戳）

### FR-4: 商品链接结构化存储与查询
- FR-4.1: 采集结果拆分为独立的 ProductLink 记录，每条商品链接一行
- FR-4.2: ProductLink 包含结构化字段：平台、关键词、页码、URL、标题、价格、销量、店铺、图片等
- FR-4.3: ProductLink 按 URL 全局去重（upsert），新采集自动合并更新
- FR-4.4: 支持按任务分页查询商品链接
- FR-4.5: 支持全局跨任务查询商品链接（按平台、关键词、任务 ID 过滤）
- FR-4.6: 支持下载任务采集结果为 JSON 文件

### FR-5: 任务管理增强
- FR-5.1: 系统跟踪所有运行中的 asyncio Task（`_running_asyncio_tasks` 字典）
- FR-5.2: 取消任务时同时取消对应的 asyncio 协程
- FR-5.3: 任务完成后自动从跟踪字典中移除
- FR-5.4: 支持取消 WAITING_HUMAN_INPUT 状态的任务
- FR-5.5: 日志步骤支持同 step 更新（幂等）
- FR-5.6: 支持多种任务类型：taobao_link_search、jd_link_search、tmall_link_search、taobao_keyword_search、search_by_urls

### FR-6: 前端页面更新
- FR-6.1: 全新设计的深色主题 UI（Outfit + Syne 字体，更深的背景色系）
- FR-6.2: 创建任务时支持设置定时规则
- FR-6.3: 任务列表展示定时规则和上次执行时间
- FR-6.4: 任务操作按钮支持重试和取消

## Success Criteria

1. 定时任务按设定规则自动触发，误差不超过 1 分钟
2. 按 URL 检索能覆盖淘宝、京东、天猫三大平台，价格提取准确率 > 90%
3. 断点续跑后已采集数据 100% 保留，新数据正确去重合并
4. 商品链接查询响应时间 < 500ms（万级数据量）
5. 取消任务后 asyncio 协程在 5 秒内停止
6. 前端页面在新主题下功能正常，无布局错乱

## Assumptions

- 定时调度器基于 Sanic 应用内的 asyncio 循环实现，不依赖外部调度服务（如 Celery）
- 按 URL 检索依赖已有的浏览器上下文，不需要额外登录
- 商品链接的 URL 标准化由各采集脚本负责，ProductLink 按 URL 去重
- 定时规则的 cron 解析使用标准库或轻量第三方库
- ProductLink 的 `synced` 字段预留给后续飞书同步功能，本版本不实现

## Out of Scope

- 不实现飞书同步（ProductLink.synced 字段仅预留）
- 不实现 cron 表达式的可视化编辑器（用户直接输入表达式）
- 不实现定时任务的通知和告警
- 不实现价格变化的自动通知（如价格下降提醒）
- 不实现分布式调度（仅单实例）
