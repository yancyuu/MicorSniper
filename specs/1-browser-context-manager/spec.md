# Feature Spec: 浏览器上下文管理与任务监控

## Overview

重构 Micro-Sniper 为聚焦的核心系统：**浏览器上下文管理 + 任务执行监控**。用户通过前端页面按渠道（小红书、抖音等）管理持久化的浏览器上下文，创建任务时挂载指定上下文，执行任务时右侧面板实时展示浏览器页面状态和执行进度。

## Problem Statement

当前系统功能过于庞大，包含了大量不需要的 Agent、连接器逻辑和复杂的业务流程。用户实际只需要：
1. 管理多个浏览器上下文（按渠道分组，如"小红书-账号1"、"小红书-账号2"）
2. 创建任务时选择一个上下文挂载
3. 任务执行过程中实时看到浏览器页面在做什么

## User Scenarios & Testing

### 场景 1：创建浏览器登录态
- 用户点击"添加登录态"按钮
- 弹出"编辑登录态"弹框，包含两个选项卡：「云浏览器登录」和「账号密码托管」
- 云浏览器登录方式：填写目标网址（如 xiaohongshu.com），点击"启动云浏览器"
- 系统创建临时云浏览器 session，弹出监控页面（含云浏览器访问 URL）
- 用户在云浏览器中手动完成登录操作
- 登录完成后用户点击"我已经登录"
- 后端关闭 session、落盘 cookies、获取 context_id 并持久化
- 登录态状态变为"已登录"，可被任务引用
- 账号密码托管方式：用户输入平台账号密码，系统自动完成登录（预留接口）

### 场景 2：管理多个上下文
- 用户可以看到所有渠道的上下文列表，按渠道分组显示
- 每个上下文显示：名称、渠道、状态（已登录/未登录/使用中）、创建时间
- 用户可以删除不需要的上下文
- 用户可以给上下文设置备注名称（如"工作号"、"个人号"）

### 场景 3：创建并执行任务
- 用户点击"创建任务"，选择任务类型（脚本或自定义）
- 用户选择一个可用的浏览器上下文挂载到任务
- 用户输入任务参数（脚本内容或配置）
- 任务开始执行，系统使用选定的上下文创建浏览器会话
- 右侧监控面板实时显示浏览器页面截图和执行步骤日志

### 场景 4：任务执行监控
- 任务执行时，右侧面板显示：
  - 浏览器实时截图（定时刷新）
  - 当前执行步骤名称和状态
  - 执行日志列表（步骤名、时间、状态）
  - 进度条
- 用户可以随时取消正在执行的任务
- 任务完成后显示最终结果

### 验收场景
- 能成功创建、登录、删除浏览器上下文
- 任务能正确使用指定上下文执行浏览器操作
- 监控面板能实时反映任务执行状态
- 多个上下文可同时被不同任务使用

## Functional Requirements

### FR-1: 浏览器上下文管理
- FR-1.1: 用户可以按渠道（小红书、抖音、微信等）创建新的浏览器上下文
- FR-1.2: 每个上下文有唯一标识、渠道类型、备注名称、状态、创建时间
- FR-1.3: 上下文状态包括：未登录、已登录、使用中
- FR-1.4: 用户可以对未登录的上下文发起登录流程（打开云浏览器）
- FR-1.5: 登录完成后用户确认，系统保存 cookies 并更新状态为"已登录"
- FR-1.6: 用户可以删除上下文（使用中的不可删除）
- FR-1.7: 用户可以为上下文设置备注名称

### FR-2: 任务管理
- FR-2.1: 用户可以创建任务，选择任务类型（脚本执行）
- FR-2.2: 创建任务时必须选择一个"已登录"状态的浏览器上下文
- FR-2.3: 选定的上下文在任务执行期间状态变为"使用中"
- FR-2.4: 任务执行完毕后（成功/失败/取消），上下文状态恢复为"已登录"
- FR-2.5: 用户可以查看任务列表及其状态
- FR-2.6: 用户可以取消正在执行的任务
- FR-2.7: 任务参数支持自定义脚本内容

### FR-3: 任务执行监控
- FR-3.1: 任务执行时，右侧面板显示浏览器实时截图（每 3-5 秒刷新）
- FR-3.2: 监控面板显示当前执行步骤的名称和状态
- FR-3.3: 监控面板显示执行日志列表（步骤编号、名称、时间、状态）
- FR-3.4: 监控面板显示整体进度条
- FR-3.5: 用户可以在监控面板中取消任务

### FR-4: 前端页面布局
- FR-4.1: 左侧面板：浏览器上下文管理区域，按渠道分组展示
- FR-4.2: 中间面板：任务列表和任务创建表单
- FR-4.3: 右侧面板：任务执行监控（截图 + 日志 + 进度）
- FR-4.4: 响应式布局，三个面板可折叠

## Success Criteria

1. 用户可以在 30 秒内完成一个新浏览器上下文的创建
2. 登录流程从打开云浏览器到确认完成，界面操作不超过 3 步
3. 任务监控截图延迟不超过 5 秒
4. 上下文状态在任务开始和结束时准确切换
5. 删除无关代码后，代码库体量减少 40% 以上
6. 系统只保留核心功能，无冗余的 Agent 和复杂业务逻辑

## Assumptions

- 浏览器上下文基于 AgentBay 云浏览器服务，持久化存储 cookies
- 任务脚本由用户自行编写，系统提供执行环境和上下文注入
- 上下文与任务是 1:1 互斥关系：一个上下文同一时间只能被一个任务使用，防止平台封号
- 保留现有的 Sanic 异步框架和 Tortoise ORM 数据层
- 保留 Redis 用于分布式锁和状态同步
- 前端保持 vanilla HTML/CSS/JS 方案

## Clarifications

### Session 2026-05-06

- Q: 任务的"脚本内容"具体是什么形式？ → A: Option B — Python 异步函数体，系统注入 `page`（Playwright Page 对象）和 `context` 信息，类似 `async def run(page, context): ...`
- Q: 登录态的创建流程？ → A: 点击"添加登录态" → 弹出"编辑登录态"弹框，包含"云浏览器登录"和"账号密码托管"两个选项卡 → 云浏览器方式：填写目标网址（如 xiaohongshu.com）→ 点击"启动云浏览器" → 弹出云浏览器监控页面 → 用户在云浏览器中完成登录 → 点击"我已经登录" → 后端关闭 session、落盘 cookies、获取 context_id → 后续任务执行时可选择携带此 context_id
- Q: 前端页面风格？ → A: 全新设计前端页面，不保留现有风格
- Q: 任务完成后上下文释放方式？ → A: 自动释放，任务结束后上下文状态立即恢复为"已登录"。上下文同时只能被一个任务使用（互斥），防止封号
- Q: 保留哪些渠道？ → A: 小红书 + 抖音
- Q: 账号密码托管是否实现？ → A: 不实现，仅做云浏览器登录。账号密码托管不预留 UI
- Q: 第一个异步任务？ → A: 抖音爬取任务，用于验证整个上下文管理 + 任务执行 + 监控流程

## Out of Scope

- 不再保留多 Agent 架构（趋势分析、创作者监控等 Agent）
- 不再保留复杂的连接器业务逻辑（内容提取、内容收割、搜索等）
- 不再保留第三方 AI 适配器（EzLink、VectorAI 等）
- 不再保留微信相关的连接器
- 不做用户权限和多租户管理
- 不做自动化调度和定时任务
- 不做账号密码托管登录（仅云浏览器登录）
